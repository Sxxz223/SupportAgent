# Anker 智能服务完整测试情景

## 情景设定

测试者是 **Alice**，使用 **Anker Prime Charger（250W，6 Ports，GaNPrime）**，型号 **A2345**。现在同时遇到两个问题：

1. 给笔记本充电时速度很慢，并且偶尔断开；
2. 充电器的时钟屏保不显示。

充电问题经过换线、换接口、断开其他设备和清洁接口后仍然存在，最后需要查询保修并创建维修工单。时钟问题在更新固件和 App 后解决。

这样一次测试可以覆盖：问题优先、多任务拆分、动态解决路径、点击式卡片、任务进度、实时 Emoji、图片上传和识别、局部补拍、知识库检索、身份核验、订单与保修查询、工单创建、任务切换、失败后改写路径和用户最终确认。

## 开场输入

打开 `http://127.0.0.1:5173/`，点击“重新开始”，然后输入：

> 我的 Anker 充电器给笔记本充电特别慢，还会偶尔断开，而且屏幕上的时钟也不显示了，帮我看看。

如果 AI 提议把两个问题拆开处理，点击表示“分别处理”或“先处理充电问题”的卡片。

## 建议操作顺序

1. 发送开场输入，让 AI 自己识别两个问题并生成路径。
2. 接受任务拆分，先处理充电问题。
3. 优先点击页面提供的答案卡片；卡片没有准确答案时，再复制上表中的文字回答。
4. 当页面开放图片入口时，上传：`test_images/charging_contacts.png`。
5. 所有充电排查步骤均反馈“做过了，问题仍然存在”，促使路径继续更新。
6. 只有 AI 判断需要售后时，再提供 Alice、`3721` 或 `ANK-DEMO-001`。
7. 查询保修后要求创建一张维修工单，再要求一次同样操作，验证系统不会重复创建。
8. 继续处理时钟问题，先提供旧版本和未连接 Wi-Fi 的状态。
9. 按建议更新到固件 `1.2.3.2` 和 App `3.2.0`，反馈时钟恢复。
10. 点击“已经解决”确认时钟任务；充电任务应显示已经转入维修，而不是被错误标记为现场修复。

## 必须看到的前端表现

- 首次输入后才生成解决路径，不能打开页面就预设故障流程。
- 两个问题被拆分成任务，并显示各自进度与当前焦点。
- 左侧“当前状态、已确认、当前判断、后续方向”根据每次回答变化。
- AI 每次只要求完成一个主要操作，并优先提供可点击卡片。
- Emoji 随处理过程显示思考、排查、发现线索、已有进展和解决。
- 需要观察实物时才出现图片入口；上传前有预览和移除功能。
- 图片结果以字段展示；不清楚时允许局部补拍，并保留已经识别出的字段。
- Alice 只提供姓名时不能显示订单和保修；输入 `3721` 或订单号并核验成功后才可以显示。
- 保修结果应为有效，截至 `2027-08-01`。
- 维修工单只能创建一次。
- 时钟回答应符合知识库：旧固件 `1.2.1.8` 需要 Wi-Fi；固件 `1.2.3.2` 配合 App `3.2.0` 可通过蓝牙支持时钟屏保。
- 只有用户确认时钟恢复后，该任务才到 100%。
- 整个页面不得出现 API Key、连接方式或内部调试信息。
